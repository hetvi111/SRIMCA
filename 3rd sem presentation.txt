1. PROJECT ARCHITECTURE OVERVIEW
================================================================================
The SRIMCA AI Assistant is a hybrid mobile/web application designed for Shrimad
Rajchandra Institute of Management and Computer Application (SRIMCA). It provides:
1. 24x7 AI-powered inquiry resolution using Retrieval-Augmented Generation (RAG).
2. Role-based access control (RBAC) for Admin, Faculty, Student, and Visitor roles.
3. Digital Notice Board, Assignment Portal, and Study Material Distribution.
4. QR Code-based Visitor Entry & Gate Security System.
5. Email OTP Authentication & JWT Session Security.
6. Real-time Push Notifications via Firebase Cloud Messaging (FCM).

BACKEND CORE FILES
--------------------------------------------------------------------------------
1. `backend/app.py`
   - Purpose: Main application entrypoint.
   - Contains:
     * Flask app instantiation (`app = Flask(__name__)`)
     * CORS policy enabling (`CORS(app)`)
     * Registration of all API blueprints (auth_bp, admin_bp, ai_bp, notices_bp,

2. `backend/auth.py`
   - Purpose: Authentication controller & JWT manager.
   - Contains:
     * `/api/send-registration-otp`: Generates 6-digit OTP, saves to `email_otps` collection with 10-min expiry, sends email via SMTP.
     * `/api/verify-registration-otp`: Validates OTP against MongoDB.
     * `/api/register`: Hashes password with `bcrypt`, validates enrollment/employee ID, creates user document in `users` collection.
     * `/api/login`: Verifies user credentials, checks if account is approved, generates JWT token containing user ID, email, and role.
     * `token_required` & `role_required` decorators enforcing security on protected APIs.

3. `backend/config.py`
   - Purpose: Configuration file parsing environment variables.
   - Contains:
     * `MONGODB_URI`: Cloud connection string for MongoDB Atlas.
     * `JWT_SECRET_KEY`: Encryption key for JWT signature generation.
     * `SMTP_SERVER`, `SMTP_PORT`, `SMTP_EMAIL`, `SMTP_PASSWORD`: Gmail SMTP settings for sending OTP emails.
     * `HF_TOKEN`: Hugging Face access token for downloading SentenceTransformers models.
     * `OPENAI_API_KEY`: API key for GPT response generation.

4. `backend/database.py`
   - Purpose: MongoDB Atlas database connection manager.
   - Contains:
     * `PyMongo` / `MongoClient` connection singleton with retry logic.
     * Helper functions retrieving collection handles: `get_users_collection()`,
       `get_notices_collection()`, `get_visitor_records_collection()`,
       `get_knowledge_collection()`, `get_ai_logs_collection()`.

5. `backend/models.py`
   - Purpose: Data models and schema structure definitions.
   - Contains:
     * Dictionary templates and validation functions for:
       - User Document (name, email, password_hash, role, enrollment_no, department, is_approved)
       - Notice Document (title, content, target_role, department, posted_by, created_at, is_pinned)
       - Assignment Document (title, subject, target_class, due_date, file_url, created_at)
       - Visitor Record (visitor_id, name, phone, purpose, host_faculty, qr_code, status, check_in_time)
       - AI Log Record (query, answer, confidence_score, duration_ms, timestamp)

6. `backend/firebase.py`
   - Purpose: Firebase Admin SDK integration.

--------------------------------------------------------------------------------
SRIMCA RAG AI ENGINE FILES
--------------------------------------------------------------------------------
14. `backend/srimca/srimca_rag.py`
    - Purpose: Master AI engine class.
    - Contains:
      * Orchestrates request execution flow:
        Step 1: Check `exact_match.py` for direct keyword match.
        Step 2: Execute vector similarity search via `retriever.py`.
        Step 3: If context found, query `gpt_answer.py` (or `fallback.py` if offline).
        Step 4: Generate related question suggestions via `recommendations.py`.

15. `backend/srimca/retriever.py`
    - Purpose: Vector search implementation.
    - Contains:
      * Loads `sentence-transformers/all-MiniLM-L6-v2` embedding model.
      * Embeds incoming user text query into a 384-dimensional floating-point array.
      * Computes cosine similarity scores against all vector documents in MongoDB `knowledge` collection.
      * Returns top K (default K=3) context text chunks.

16. `backend/srimca/gpt_answer.py`
    - Purpose: OpenAI GPT Integration.
    - Contains:
      * Formats prompt with system prompt, retrieved knowledge context, and user question.
      * Calls OpenAI ChatCompletion API (`gpt-3.5-turbo` / `gpt-4o-mini`).
      * Returns structured natural language response.

17. `backend/srimca/fallback.py`
    - Purpose: Offline rule-based answer generator.
    - Contains:
      * Keyword and intent rules for SRIMCA courses (MCA, BCA, BBA, MBA), admissions, fees, timings, faculty, and location.
      * Guarantees 100% availability even without OpenAI API quota or internet connectivity.

18. `backend/srimca/build_db.py`
    - Purpose: Knowledge base indexing script.
    - Contains:
      * Reads raw text files from `backend/srimca/data/*.txt`.
      * Splits text into logical chunks (paragraphs / lines).
      * Generates 384-d vector embeddings using SentenceTransformers.
      * Inserts chunks and vectors into MongoDB `knowledge` collection.

5. MONGODB DATABASE COLLECTIONS & SCHEMA DESIGN
================================================================================

1. Collection: `users`
   - Description: Stores all user accounts across roles.
   - Fields:
     * `_id`           : ObjectId (Primary Key)
     * `name`          : String
     * `email`         : String (Unique Index)
     * `password_hash` : String (Bcrypt Hashed)
     * `role`          : String ("admin" | "faculty" | "student" | "visitor")
     * `enrollment_no` : String (Optional, for students)

6. SRIMCA RAG AI PIPELINE & EMBEDDING WORKFLOW
================================================================================

The Retrieval-Augmented Generation (RAG) system operates through a 5-step pipeline:

STEP 1: Document Processing & Vector Indexing (`build_db.py`)
- Official SRIMCA data is collected in `.txt` format under `backend/srimca/data/`.
- Text is split into small semantic chunks (100–200 words each).
- Each chunk is passed through the `sentence-transformers/all-MiniLM-L6-v2` model.
- The model generates a 384-dimensional dense vector representing the semantic meaning.
- Vectors and original text chunks are indexed into the `knowledge` collection in MongoDB Atlas.

STEP 2: Query Embedding (`retriever.py`)
- When a user submits a question in the Flutter app (e.g., "What are the passing marks for MCA?"), the backend receives the string at `/api/ai/chat`.
- The query string is encoded into the same 384-dimensional vector space using `SentenceTransformer.encode(query)`.

STEP 3: Vector Similarity Search (`retriever.py`)
- The system calculates Cosine Similarity between the query vector and all stored knowledge vectors in MongoDB:
  Cosine Similarity = (A . B) / (||A|| * ||B||)
- The top 3 chunks with highest similarity scores above threshold (e.g., score > 0.65) are selected as reference context.

STEP 4: Answer Generation (`gpt_answer.py` / `fallback.py`)
- If OpenAI API key is active: A prompt combining system instructions, retrieved knowledge context chunks, and user prompt is sent to OpenAI GPT.
- If offline/no API quota: The system invokes `fallback.py`, which maps query intent against deterministic response templates to guarantee zero-downtime answers.

STEP 5: Post-Processing & Recommendations (`recommendations.py`)
- The response, confidence score, and 2-3 suggested follow-up questions are formatted and returned to the Flutter app as JSON.
- Telemetry data is saved asynchronously to the `ai_logs` collection for admin monitoring.

7. VIVA PRESENTATION QUESTION & ANSWER CHEAT SHEET
================================================================================

Q1: What is the main objective of your project?
A1: The main objective of SRIMCA AI Assistant is to automate campus inquiry resolution 24x7 using AI RAG technology, streamline communication between students, faculty, and administration through digital notices, and modernize security gate access using QR-based visitor management.

Q2: Why did you choose Flutter for the frontend and Python Flask for the backend?
A2: Flutter allows building cross-platform apps (Android, iOS, Web) from a single codebase with native performance and rich UI. Python Flask is lightweight, highly modular, and provides seamless integration with Python AI/ML libraries like SentenceTransformers, PyTorch, PyMongo, and OpenAI.

Q3: Explain what RAG is and why you didn't just use standard ChatGPT?
A3: RAG stands for Retrieval-Augmented Generation. Standard ChatGPT doesn't know private campus data (like SRIMCA exam dates or faculty offices) and can hallucinate. RAG first retrieves factual, verified SRIMCA documents from our MongoDB vector database and feeds them to the AI model as context, ensuring 100% accurate, hallucination-free answers specific to SRIMCA.

Q4: What embedding model do you use and what is vector dimension?
A4: We use `sentence-transformers/all-MiniLM-L6-v2`, an open-source lightweight transformer model that outputs 384-dimensional dense vectors. It runs locally on the CPU without requiring paid external API tokens for embedding generation.

Q5: How is security handled in your application?
A5: Security is implemented at multiple layers:
    1. Passwords are hashed using `bcrypt` before database storage.
    2. Email OTP verification ensures valid institutional email ownership during registration.
    3. Session access is protected using JSON Web Tokens (JWT) with signature verification on all private REST APIs.
    4. Role-based access control (RBAC) ensures students cannot access faculty or admin endpoints.

Q6: How does the Visitor QR entry system work?
A6: When a visitor registers on the mobile app, the backend creates a unique visitor ID and encrypts it into a QR code PNG image. At the gate, security scans the QR code using the app. The scanner sends the scanned ID to `/api/visitor/qr/checkin`, which checks MongoDB and verifies whether the visitor is approved by host faculty, changing their status to "checked-in".

Q7: What happens if the internet connection or OpenAI API goes down?
A7: Our system features an intelligent dual-engine fallback system (`fallback.py`). If the OpenAI API is unreachable or rate-limited, the backend automatically switches to intent-matching and rule-based keyword responses, guaranteeing that users still get instant, reliable answers offline.

Q8: What database are you using and why MongoDB Atlas over SQL?
A8: We use MongoDB Atlas (Cloud NoSQL). MongoDB was chosen because knowledge chunks, AI logs, and user profiles have flexible schemas, and MongoDB Atlas offers built-in cloud hosting, automated scaling, TTL indexes for OTP deletion, and high performance for vector array storage and JSON API responses.

Q9: What packages did you use in Flutter for state management and networking?
A9: We used the `http` package for REST API communication, `shared_preferences` for persistent JWT session storage, `firebase_messaging` & `flutter_local_notifications` for push notifications, `qr_flutter` & `mobile_scanner` for QR rendering and scanning, and standard Flutter StatefulWidgets / Providers for state management.

10: What are the future enhancements planned for this project?
A10: Future enhancements include:
     1. Multimodal RAG capable of processing PDF syllabus documents, handwritten notes, and images.
     2. Voice-guided conversational AI in local languages (Gujarati/Hindi).
     3. Automated AI assignment grading for faculty.
     4. Progressive Web App (PWA) offline installation.
